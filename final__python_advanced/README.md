### Введение
Поставлена задача по реализации бэкенда корпоративного сервиса микроблогов.
Поскольку это корпоративная сеть, то функционал урезан относительно оригинала.

Реализация выполнялась в исключительно свободное от работы и иных задач время.
Для реализации проекта использовались как ранее выполненные задачи (в рамках 
выполнения практических заданий при обучении), так и многочисленные материалы
из сети Интернет.

### Общее описание проекта
Что именно реализовано в данном проекте (что умеет микросервис):
- Пользователь может добавить новый твит (текст + картинки, так и только 
текст).
- Пользователь может удалить только свой твит.
- Пользователь может зафоловить другого пользователя.
- Пользователь может отписаться от другого пользователя.
- Пользователь может отмечать твит как понравившийся.
- Пользователь может убрать отметку «Нравится».
- Пользователь может получить ленту из твитов отсортированных в порядке 
убывания по популярности от пользователей, которых он фоловит.

Для демонстрации функционирования проекта база данных предварительно заполнена 
фейковыми данными. Генератор фейковых данных запускается через 
"make_fake_data.py". Параметры для подключения к базе данных в файле .env или 
через переменные среды окружения. База данных для тестирования создаётся
отдельно при запуске тестов. Тестирование предусмотрено только в среде для
разработки приложения.

Конечный продукт работает через docker. Приложение backend, сервер nginx и 
СУБД Postgresql функционируют в отдельных контейнерах.

### Подготовка проекта к запуску
Для развёртывания приложения необходимо установить docker и docker-compose:
[Документация на официальном сайте](https://docs.docker.com/engine/install/ubuntu/).

Размещаем файлы приложения в каталоге, где будут размещатьсяЮ помимо исходных 
файлов проекта, каталоги баз данных и логов, загруженные файлы изображений к 
твитам. Развернуть приложение можно как из [репозитория](https://gitlab.skillbox.ru/evgenii_tiavkin/python_advanced_diploma.git),
так и из архива, загруженного из репозитория автора.

В каталоге приложения для файлов с расширением .sh необходимо установить
разрешение на запуск:
> sudo chmod u+x *.sh

Запускаем "**./prepare_dirs.sh**" для подготовки каталогов. Внимание! При
работе скрипта вызываются sudo для изменения владельца и прав доступа к 
каталогам. Поэтому, может быть запрошен пароль root пользователя.

*В каталогах **./db/** и **./db_test/** будут располагаться непосредственно 
файлы баз данных. В каталоге **./logs/** будут храниться протоколы приложений 
проекта. Файлы, которые будут загружать пользователи проекта, будут сохранены 
в **./server_nginx/static/images/**. Если у этих каталогов убрать права на
запись, то это спровоцирует ошибки в работе частей проекта!*

Для настройки подключения к базе данных потребуются файлы "**.env_prod_db**"
(для СУБД Postgres) и файл "**.env**" (для приложения FastAPI). Примеры
содержимого указанных файлов:
> **.env_prod_db**
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=micro_db
POSTGRES_HOST=postgres:5432
ONLY_USER=admin
ONLY_USER_PASSWORD=admins@password
> **.env**
POSTGRES_USER=admin
POSTGRES_PASSWORD=admins@password
POSTGRES_DB=micro_db
POSTGRES_HOST=postgres:5432

Т.е. в файле **.env_prod_db** параметры POSTGRES_USER и POSTGRES_PASSWORD
соответствуют пользователю postgres с максимальными привилегиями.

Запуск проекта через файл "**./start_prod.sh**", который через "docker-compose"
развернёт контейнеры и запустит их. В файле "docker-compose.yml" параметр 
"restart" предусматривает перезапуск контейнера при отказе. Поэтому,
достаточно однократного запуска. Если потребуется остановить приложение и
убрать контейнеры, то выполните "docker-compose down" в каталоге проекта.

### Работа с проектом
В браузере переходим на адрес "http://127.0.0.1/" (при подключении с других
устройств в рамках сети потребуется указать адрес станции (сервера), на 
которой развёрнуто приложение, например, http://192.168.1.2/). Для доступа по
доменному имени станции (сервера) необходимо в файле "./server_nginx/nginx.conf"
в строке "server_name" указать имя станции (сервера). Для доступа к документации
перейдите на http://127.0.0.1/docs или http://127.0.0.1/redoc в браузере.

На главной странице справа сверху указываем ключ (логин) пользователя.
Если такого ключа в базе данных нет, то получите отказ (ошибку) аутентификации.
Там же параметр "Пагинация" (при включении) позволяет отображать твиты с
разбивкой по страницам. Количество записей по умолчанию 5. Очерёдность
твитов отображается в соответствии с техническими требованиями.

Через профиль абонента (который опубликовал твит) можно подписаться (читать) 
или убрать из подписки (прекратить читать). Размещение твитов возможно как
с картинкой (размер файла не более 2 Мб), так и только текст. Лайки пользователь
может ставить не зависимо от автора твита. Удалить твит можно только свой.
